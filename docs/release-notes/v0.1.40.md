# v0.1.40

DeepSeek 日期版本基线、指纹优先调度和检测速度优化。

## 日期版本基线

- 新增 `DeepSeek-V4.1-Flash-0910`：从之前保存的官方 API 采集重建，36 个训练样本 + 12 个验证样本，验证 4/4 命中。
- 新增 `DeepSeek-V4.1-Flash-1017`：使用 `https://api.deepseek.com` 和模型名 `deepseek-flash` 采集，36 个训练样本 + 12 个验证样本，48/48 次请求有效，验证 4/4 命中。
- 数字候选从 18 个增加到 20 个；可测模型清单从 40 个增加到 42 个。
- `deepseek-flash` / `deepseek-v4.1-flash` 只作为请求名或历史别名，不再作为归因候选显示。实际归因显示带日期的 `DeepSeek-V4.1-Flash-0910` 或 `DeepSeek-V4.1-Flash-1017`。
- 第三方网关如果返回旧日期版本或别的模型，报告会显示实际命中的日期版本并判定不一致；当前官方 API 的 `deepseek-flash` 实测归因为 `DeepSeek-V4.1-Flash-1017`（97.8%，3 个样本，24.6 秒）。

## 指纹归因

- 只要声称模型所属家族在数字库里有候选，就直接采样并和整库候选比较，不再因为“请求名不是库内 ID”直接落到“未建立数字基线”。
- 没有数字基线的家族（Gemini / Grok / GLM / Kimi 等）改为和 34 个行为候选直接比对。强匹配显示实际模型；候选接近或相似度偏低时显示“证据不足”，不盖假章、不判掺水。
- 行为归因新增“数字归因 / 行为归因”标识，弱证据不会因为 `low_confidence` 被前端扣分。

## 指纹优先与速度

- 检测开始时先启动模型指纹归因，并让它先占用上游请求槽位；其它板块仍然并发执行，不串行等待指纹完成。
- 3 个行为探针从串行改为并发。
- IQ 提问提示改为直接给结论、不展开可见推导，减少长尾单题耗时。

## UI

- 模型选择器改为自定义下拉：搜索、键盘操作、细滚动条、手机端自动向上展开，避免原生 datalist 的黑色滚动条和裁字。
- 指纹卡显示日期版本模型名、行为相似度、候选条和归因依据；行为归因不再重复展示数字挑战证据。

## 验证

- Go 全量测试、`go vet`、相关包 `go test -race` 通过。
- 前端 24 项测试、`typecheck`、`build` 通过。
- 官方 DeepSeek API 端到端：`deepseek-flash` → `DeepSeek-V4.1-Flash-1017`，`top_prob=0.978`，`used_outputs=3`，耗时 24.6 秒。

## 升级注意

- 线上 SQLite 的 `runtime_state` 里可能缓存了旧指纹库快照（`modeltrace-bank-v1`）。升级后必须清掉这一行并重启，否则旧的通用 DeepSeek 别名会继续出现。
- 历史报告是保存时的快照，不会因本次基线更新自动重算；新提交的检测使用新库。
