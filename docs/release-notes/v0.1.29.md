# v0.1.29

修复报告页崩溃，适配 thinking.display=updates，加长上游 5xx 后的重试退避。

## 报告页崩溃

线上 `/history` 报 `TypeError: Cannot read properties of null (reading 'length')`，
整页白屏。隐藏指令检测没有命中证据时，后端把空的 `signals` / `asks` 输出成 `null`，
报告页读 `.length` 就崩。

- 后端改为输出 `[]`。
- 前端读取时兜底为空数组，v0.1.27 / v0.1.28 已落库的旧报告也能正常打开。

## thinking.display=updates

`display=updates` 要求请求头带 `anthropic-beta: thinking-display-updates-2026-08-18`，
没带时官方只认 `summarized` / `omitted`，回 400。

- 网关在请求体用到 `updates` 时自动补上这个 beta 头。
- 调用方自己带的 `anthropic-beta` 原样保留、合并去重，不会被覆盖或删掉。
- 单问单答面板新增「自适应 + 进度更新（beta）」。

## 上游 5xx 退避加长

一批长输出请求并发打出去时，上游会成片回 `500 new_api_error`。原来的重试间隔是
250ms / 500ms / 1s，三次重试都落在同一阵拥堵里，全部失败。5xx 改为 2s / 4s / 8s，
并加最多 25% 的随机抖动，避免一起失败的探针同步重试再撞一次。其它错误仍是短退避。

## 内部

- `scripts/deploy-release.ps1` 改用 `certutil` 计算 SHA256，不再依赖 `Get-FileHash`。
