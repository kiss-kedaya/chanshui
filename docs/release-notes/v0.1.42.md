# v0.1.42

只读缓存模型验证修复。

## 问题

部分上游只回传缓存读取（`cached_tokens` / `cache_read_input_tokens`），不回传缓存写入/创建字段；首轮连读取字段也可能缺失。旧逻辑要求每一轮同时有读和写，首轮缺字段时把上一轮基线算成 0，显示“无法验证”和 0/5，尽管第 2～6 轮已经稳定读到同一段缓存。

## 修复

- 允许首轮读取字段缺失；从首个已上报读取开始验证读取链。
- 只读链至少有 2 个已上报读取，末轮读取大于 0，即通过。
- 上一轮基线使用最近一次已上报读取，不把缺失的写字段当成 0。
- 每轮命中率 = 本轮读取 ÷ 本轮总输入；末轮缓存率 = 末轮读取 ÷ 末轮总输入。
- 首轮未上报读取时命中率保持 `—`，后续轮次正常显示百分比。
- 前端“上一轮读 ＋ 写”在只读链改为“上一轮读取”，显示实际值。

## 实测样本

用户提供的 6 轮数据：

- 第 1 轮：读取/写入字段未上报，输入 1909。
- 第 2～6 轮：读取稳定 1792，写入未上报。
- 末轮总输入 2039。

修复后：`1792 ÷ 2039 = 87.89%`，缓存项 5/5 通过。

## 验证

- `go test ./internal/cachecheck ./internal/api` 通过。
- 新增冷启动只读回归：首轮缺读取字段、后续稳定读取，断言通过、基线 1792、末轮率 87.89%。
- 前端缓存卡新增只读冷启动用例；前端 25 项测试、`typecheck` 通过。
