# v0.1.38

数字指纹库对齐官方 ModelTrace，不再维护自有采样基线。

- 内置库更新到官方当前版本 `6cd4a8f`（2026-10-09），候选 18 个。
- 移除全部本地采样基线（`deepseek-v4.1-flash`、`grok-4.6`、`grok-4.7`）及其保留集、采集证据和专属测试。
- 参考 oracle 按官方库重新生成，Go 实现与官方 Python 打分校准一致。

## 为什么改

自有基线与官方库的候选集不一致：本地基线来自单接口、单一环境采样，官方候选来自 12 组独立环境。两套数据放在同一个候选集里会互相干扰，而不是互相补充——例如 `gpt-6.1-sol` 与其邻近候选在同一接口上的分布距离（L1 0.040）比同一模型跨接口的距离（L1 0.049）还小。

对齐官方后归因只在官方维护的候选之间比较，口径统一，也不会因为本地采样条件变化而漂移。上游库每 6 小时自动同步一次，内置库与线上缓存现在始终一致。

## 影响

- 未在官方候选集内的模型（含 `gpt-6.1-sol`、`claude-fable-5`、DeepSeek、Grok）指纹项走"未建立数字基线"分支，记 0 分，不再给出可能来自自有基线的归因。
- 官方候选内的模型（GPT 系列、Claude 系列）归因不受影响。

## 保留项

以下属于独立功能，不属于指纹数据，未改动：

- 自定义模型名称（前后端端到端）
- 协议选择中的供应商前缀处理
- 低置信指纹不再判定为掺水

## 验证方式

- 打开历史页，可检测清单为官方 18 个候选。
- 提交 `gpt-6.1-sol` 检测，指纹项显示"未建立数字基线"，不再返回归因。
- 提交 `claude-opus-5` 检测，指纹项正常归因。
