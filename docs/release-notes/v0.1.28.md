# v0.1.28

修复指纹归因的稳定性，并补上 thinking 参数的一个合法值。

## 指纹归因改走非流式

数字指纹题要一次输出几百个数字，属于长响应。同一题面各跑 6 次实测：

- 非流式：6/6 成功
- 流式：1/6 断在半路

断流的表现是 HTTP 头已经回了 200，响应体却被提前掐断，没有 `message_stop`。
数字样本只看最终文本，不需要逐字回传，所以改走非流式。

## 断流不再报成上游 5xx

`stream.go` 一直能识别「没有 message_stop」，但错误文案笼统写成「上游服务异常」，
让人误以为上游挂了。现在单独分类为「上游响应流被提前中断（连接在传输中途结束），
可重试」，与 5xx 区分。

## thinking display 补上 highlights

上游接受 `display=highlights`（`claude-opus-5-5` 实测返回 200），但后端白名单只认
`summarized` / `omitted`，把用户挡在门外。现在补上，「单问单答」面板同步加了
「自适应 + 要点」。

`disabled` 保留：该面板本来就是给用户探网关用的，发 `disabled` 看上游认不认是有效
探测。标注改成「明确关闭（部分模型不支持）」——`claude-opus-5-5` 明确拒绝该值，
`claude-sonnet-5` / `sonnet-4-5` / `opus-4-6` / `haiku-4-5` 接受。

## 402 余额不足不再重试

账户没钱时重发同样的请求只会得到同样的结果，此前会白烧 4 次重试，现在直接返回。

## 内部

- 部署脚本改为两段式（`scripts/deploy-release.ps1`）：本机用已登录的 gh 下载包
  并校验 sha256，再 scp 上传；服务器只校验同一个 hash 并解到新版本目录。仓库是
  私有的，服务器直连 Release 会 404。
- `internal/injection` 与 `internal/api/jobs.go` 通过 gofmt。
